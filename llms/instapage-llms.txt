# Instapage

> Instapage is a landing page and post-click optimization platform for paid-advertising teams. The
> Instapage Public API (REST, v1) gives programmatic access to workspaces, team members, landing
> pages, page groups, personalized experiences, collections, experiments, analytics, form
> submissions (leads), custom domains and image assets. Authentication is a Personal API Token sent
> as an HTTP Bearer token; rate limiting is 200 requests/minute per token and per IP on top of a
> daily plan quota that resets at 00:00 UTC.

Generated by API Evangelist from the Instapage developer reference. Instapage does not publish an
llms.txt of its own — https://instapage.com/llms.txt returns the marketing site's HTML shell, and
https://devdocs.instapage.com/llms.txt returns 404.

- Base URL: https://api.instapage.com/v1
- Auth: `Authorization: Bearer <personal API token>` (generated in Instapage account settings)
- Rate limits: 200 req/min per token AND per IP; daily plan quota; 429 + `Retry-After` on exhaustion
- Pagination: `?page=` with a `meta.pagination` block; form submissions use a `nextPageToken` cursor
- Errors: `{ "title", "details", "meta" }` — no machine-readable error code, branch on HTTP status
- Idempotency: not supported; there is no idempotency key on any write operation

## Specs

Instapage publishes no OpenAPI. These are API Evangelist transcriptions of the published reference.

- [Complete OpenAPI 3.1 (all 39 operations)](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/_original/instapage-openapi.yml)
- [Workspaces](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-workspaces-api-openapi.yml): create, read, rename and delete workspaces
- [Team Members](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-team-members-openapi.yml): bulk invite, re-role and remove workspace members
- [Pages](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-pages-openapi.yml): list, search, update, delete, publish, unpublish, import and export landing pages
- [Groups](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-groups-openapi.yml): page folders inside a workspace
- [Personalizations](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-personalizations-openapi.yml): personalized experiences attached to a page
- [Collections](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-collections-openapi.yml): template-driven page collections and collection pages
- [Experiments](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-experiments-openapi.yml): A/B and AI experiments
- [Analytics](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-analytics-openapi.yml): bulk visit, conversion and lead statistics
- [Form Submissions](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-form-submissions-openapi.yml): retrieve and permanently delete lead data
- [Domains](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-domains-openapi.yml): custom domains connected to a workspace
- [Assets](https://raw.githubusercontent.com/api-evangelist/instapage/refs/heads/main/openapi/instapage-assets-openapi.yml): image folders and image upload

## Not published by Instapage

Recorded so an agent does not go looking: no OpenAPI, no GraphQL, no AsyncAPI, no webhooks, no MCP
server, no A2A agent card, no first-party SDK in any language, no CLI, no sandbox or test-mode keys,
no OAuth (personal tokens only, so no scope surface), no /.well-known/ documents, and no idempotency
key on write operations.
